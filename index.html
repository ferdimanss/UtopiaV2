👋 先讀這裡：HOST（老師）按「✨ AI 生成議題」時，系統會把一份很長的 prompt 送給 AI。 這份 prompt 由 7 段拼成，有些是老師可在大廳直接編輯的、有些是系統自動算出來的。 想調整議題效果，先看 第 2 段速查表對照「症狀 → 去哪改」最快；想理解原理再往下看。

1. Prompt 七段結構總覽

HOST 按「✨ AI 生成議題」後，送給 AI 的完整 prompt 由 7 段串接而成 （socket/aiHelper.js generateAIEvents 內 composePrompt(template, staticKnowledge, dataBlock1, dataBlock2) + schema）：

2. 「老師覺得 X 怪怪的」→ 去哪裡調整 速查表

老師的反映去哪裡調整
「議題開頭那句話太誇張 / 想改語氣」event_templates.json firstSentences（21 句，依指標 + 分數）
「某建設講出來的後果（短語）不對」actioncards.csv 那張卡的第 18 欄（全球副作用短語）/ 第 19 欄（國內效果短語）＋ 重啟
「議題內文的句型結構想改」event_templates.json templates.A/B/C
「情境 C（全球變好）那句固定話想改」event_templates.json templates.C + scenarioCPhrases
「公衛空窗期那段固定文本想改」event_templates.json publicHealthVacuum.fixedText
「環境議題不該出現某個詞 / 想加禁詞」event_templates.json environmentTaboos.forbiddenWords
「某指標配的懲罰（debuff）想換」event_templates.json debuffByIndicator（同時確認 World.csv id 15-17 狀態名一致）
「公衛空窗期主角不該是綠境/新生」event_templates.json publicHealthVacuum.candidatePrimaryCountries
「主影響國判定怪怪的（選錯國）」程式邏輯 eventComputation.js selectPrimaryCountries
「受損國判定怪怪的」程式邏輯 eventComputation.js identifyDamagedCountries
「國名 / 國家背景 / 優勢 / 初始數值不對」World.csv 對應列 ＋ 重啟
「建設的數值（效果/副作用）不對」actioncards.csv 對應卡列 ＋ 重啟
「AI 角色語氣 / 標題字數 / 內文字數要求」event_generation.md（或大廳即時改）
「議題數值範圍 / 要不要 AI 生數值」HOST 大廳「🎲 AI 數值生成設定」
「附帶狀態要正面還負面」HOST 大廳「附帶狀態類型」勾選
「schema 結構 / 禁止項措辭」程式 aiHelper.js（工程師改）
重點提醒：改 event_templates.json、actioncards.csv、World.csv 之後都要重啟 server 才生效（這些都有快取）。HOST 大廳的 prompt / 數值設定是即時生效，但 prompt 重啟會還原成 MD 檔。

5. 目前系統的幾個刻意設計 / 上限

以下是系統目前的幾項客觀現況，當結果跟直覺不同時可先對照，知道是「刻意這樣設計」而非異常。

📐 全球副作用核心短語：只取「扣本議題指標」的建設

議題內文裡「並進一步引發全球 ○○○」那段粗體，填的是主影響國建設造成的全球副作用短語（來自 actioncards.csv 第 18 欄）。 目前程式（convertBuildingsToPhrases）只取「對本議題指標扣分」的建設的短語，不放主影響國其他指標的建設短語。

  • 舉例：工業聯盟同回合蓋了「工業區」（扣生態環境 −2）+「金融中心」（扣健康衛生 −1），它成為生態環境議題主影響國 → 只放工業區的「周邊跨國棲地退化…」，金融中心扣的是健康衛生、不放它的短語。
  • 這樣設計的好處：① 主題一致（生態環境議題不會冒出「藥品分配」這種醫療字眼）； ② 不踩環境禁忌詞；③ 因果乾淨（這則講生態變糟，就只列造成生態變糟的建設）。
  • 若想改成「放所有建設短語」：要動 eventComputation.js convertBuildingsToPhrases， 把全球副作用短語的篩選從「只取 b[w] < 0」放寬成「取所有 b.globalSidePhrase 非空的建設」。
實務上多數情況兩種做法結果相同 —— 主影響國通常是「因為扣了這個指標才被選為主影響國」，建設大多在扣同一指標。只有「主影響國同時蓋了影響別指標的建設」這種較少見情況才有差。

📐 平手判定：第二排序用「該國本回合所有建設的國內效果絕對值總和」

當兩國對某指標的「扣分絕對值總和」完全相同（平手）時，用「本回合因建設獲得的國內效果（國力收益）絕對值總和」當第二排序，高者當主影響國。 目前程式（aggregatePerCountryIndicatorScore 的 domesticAbsSum）是把該國本回合所有建設的 v1/v2/v3 絕對值全加。

  • 觸發極罕見：要兩國「扣分絕對值總和剛好一模一樣」才會用到，本身就很少發生。
  • 結果幾乎一樣：會走到平手的兩國建設組合通常相近，全加 vs 只加扣分建設的排序大多不變。
  • 若想只算扣分建設：改 eventComputation.js aggregatePerCountryIndicatorScore， 把 domesticAbsSum 改成「只在 b[w] < 0 的建設上加 v1/v2/v3 絕對值」。

📌 副影響國上限：最多 3 國

「情境 A 集體擺爛」時受損國敘述文字會寫「其餘五國」，但 aiHelper.js _buildEventFromDirective 把實際記錄的 secondaryTeams（副影響國）截斷成最多 3 國。

  • 避免一則議題塞 5 個副影響國，後續評語會太雜。
  • 純粹是「畫面敘述文字」與「實際記錄副影響國數」不完全對齊，不影響運算。

6. 附：規則引擎判定流程（理解用，非調整入口）

本回合各國建設（teamBuilt 本回合部分）
  → 算各指標全球總分
  → 依序判定 3 個主影響國（生活經濟→生態環境→健康衛生，排他遞補）
  → 各指標判情境：總分>0且無人扣分=C / 總分>0=B / 否則=A
  → 場景第一句（依指標+總分，區間截斷 ±3）
  → 主影響國扣分建設 → 提取短語（去重、最多 2 種、扣分最高優先）
  → 受損國 4 原則（公衛空窗期→情境C→有人加分擦屁股→集體擺爛）
  → 依指標配 debuff
  → 特例：六國都沒碰健康衛生 → 公衛空窗期，主角綠境/新生隨機 2 選 1，固定文本

每一步對應的函式與檔案見 docs/structure.md §3.6.1。
